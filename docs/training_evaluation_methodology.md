## 0. 背景

已经从openpilot项目的driving_vision.onnx模型文件中提取checkpoints/inadas_original.pt和checkpoints/inadas_original.onnx模型文件。并且已经验证提取的模型文件精度与原模型高度一致。

本方案对checkpoints/inadas_original.pt进行微调，以使得模型时应多种相机安装高度场景。

## 1. 总体策略

采用 **"隐式优先，显式增强"** 两阶段策略（详见 height_extension_design.md §2.5.5）：

```
第一阶段（隐式基线）
  └─ 多高度联合训练（H1–H6），不添加高度输入
  └─ 直接微调 openpilot 预训练模型（23M 参数）
  └─ 量化各高度精度，建立基线
  └─ 若满足判定标准 → 直接部署

第二阶段（显式增强，按需）
  └─ 在第一阶段权重基础上添加 HeightConditionedHead
  └─ 利用连续高度嵌入实现中间高度平滑插值
  └─ 端到端全量微调
```

**核心原则**：

1. **利用预训练知识**：openpilot 23M 参数 backbone 在数百万英里真实驾驶数据上训练，是极强的初始化，微调而非从头训练
2. **高度无关性**：LDW 关键输出 `y_lat` 和 FCW 关键输出 `x_fwd` 在标定帧中本身高度无关，降低学习难度
3. **渐进微调**：分层学习率 + 渐进解冻，防止灾难性遗忘

## 2. 数据准备

### 2.1 数据来源与格式

数据由 collect_annotate_plan.md 描述的流水线产生：

```
Carla 多高度同步采集（Step A）
    → 离线标注 annotate_multi_height.py（Step B）
    → 预处理缓存 preprocess_cache.py（Step C）
    → 训练用 .npz 缓存文件
```

**单个训练样本包含**：

| 字段 | 形状 | 类型 | 说明 |
|------|------|------|------|
| `road_yuv` | `(6, 128, 256)` | uint8 | 窄焦相机 warp 后 YUV420 |
| `wide_yuv` | `(6, 128, 256)` | uint8 | 广角相机 warp 后 YUV420 |
| `camera_height` | scalar | float32 | 相机安装高度（米） |
| `lane_lines` | `(4, 33, 3)` | float32 | 车道线 [x, y_lat, z_height] |
| `lane_lines_prob` | `(4,)` | float32 | 车道线置信度 |
| `road_edges` | `(2, 33, 3)` | float32 | 路沿 [x, y_lat, z_height] |
| `lead` | `(3, 6, 4)` | float32 | 前车 MDN [x, y, v, a] |
| `lead_prob` | `(3,)` | float32 | 前车存在概率 |
| `pose` | `(6,)` | float32 | 运动状态 |
| `road_transform` | `(6,)` | float32 | 路面几何变换 |
| `wide_from_device_euler` | `(3,)` | float32 | 宽窄相机相对姿态 |

**注意**：模型输入为 `prev_frame + curr_frame` 拼接的双帧输入，shape 为 `(12, 128, 256)`（窄焦）和 `(12, 128, 256)`（广角），缓存文件中应已包含时序帧对。

**数据清洗规则**：
- **时序抽帧**：每 5 帧抽选 1 帧（即每 1 秒选 1 帧）。采集阶段 `save_every=4` 对应 5 FPS，抽帧后等效 1 FPS。在典型行驶速度（60 km/h）下相邻训练帧间距约 16.7m，基本消除时序冗余，同时避免训练/验证/测试集之间因相邻帧高度相似而产生数据泄漏。
- 只有当L-inn和R-inn的标注置信度都超过0.3时才选择该帧数据；
- 对于被选中的数据帧：
  - 从原始数据集中找到它的PRE帧，读取图像保存；
  - 训练数据的车道线/路沿置信度处理：
    - **lane_lines_prob**：保留教师模型的原始概率值作为软目标（不二值化）。理由：(1) 已通过 L-inn/R-inn > 0.3 帧级过滤，被选中帧的内侧车道线置信度本身较高；(2) 外侧车道线（L-outer, R-outer）的低置信度反映真实可见性（部分遮挡、画线模糊等），保留这一信息有助于模型学习合理的不确定性；(3) 软标签是知识蒸馏的标准做法，比硬标签包含更多信息。
    - **road_edges_prob**：标注中已固定为 1.0（模型无 per-edge 概率输出），直接保留。
  - Lead数据清洗：**将 lead_prob 二值化为 0.0/1.0**。具体规则：
    - 对 3 个时间偏移（t=0/2/4s）独立处理：若原始 `lead_prob[i] ≥ 0.5`，设为 `1.0`；否则设为 `0.0`
    - 当 `lead_prob[i] = 0.0` 时，对应的 lead 位置数据 `(x, y, v, a)` 标记为无效（训练时 mask 掉该时间偏移的位置损失，不贡献梯度）
    - 理由：(1) 教师模型在 lead_prob 0.3–0.7 区间的输出噪声大，对应的位置预测不可靠，保留这些软概率会向学生模型注入噪声；(2) 前车检测在部署中本质上是二值决策（存在/不存在），二值化目标更贴近实际使用；(3) 当 lead_prob < 0.5 时，位置数据质量不可信，必须 mask 以防止模型学习错误的空间映射
- 通过清洗的数据应该另外保存。

### 2.2 训练/验证/测试集划分

清洗后的数据按帧打乱，按照 8/1/1 比例随机划分为训练/验证/测试数据集。

### 2.3 H1 退化验证集

从标注数据中**单独抽选一个 H1 专用验证集**，不参与训练，专门用于训练过程中监控标准高度（H1=1.22m）是否发生退化。

**抽选规则**：
- 来源：H1 高度的已标注数据
- 抽选比例：H1 总数据的 10%（按帧随机抽选，与训练/验证/测试集的划分独立进行）
- 该数据集在训练集、验证集、测试集划分**之前**先行抽出，剩余 H1 数据再参与 §2.2 的打乱与 8/1/1 划分

**用途**：
- 每个 epoch 结束后在该集上计算 `val_loss_H1`，用于 §4.5 的灾难性遗忘防护（Early stopping 双指标中的条件2）
- 与训练初始时（epoch 0，预训练权重）的基线值对比，实时监控退化程度
- 该集不参与梯度更新，也不影响总体验证集的 early stopping 判断


### 2.4 数据增强

由于训练数据来自 Carla 仿真（场景多样性有限），需要适度数据增强以提高泛化能力。

| 增强方法 | 参数 | 目标 |
|---------|------|------|
| **亮度抖动** | ±15%（YUV Y 通道线性缩放） | 模拟不同光照 |
| **对比度抖动** | ±10%（Y 通道 histogram stretch） | 模拟不同天气/曝光 |

**不做的增强**：

- 不做几何变换（旋转、缩放、裁剪）——warp 矩阵已经确定了几何映射，额外的几何变换会破坏标注与图像的对应关系
- 不做色彩空间大幅变换——YUV 输入已经过精确的颜色转换流水线
- 不做水平翻转，以免翻转后2D和3D映射关系错误。

**进阶增强（暂时不做）**：
| 增强方法 | 参数 | 目标 |
|---------|------|------|
| **高斯噪声** | σ=2（uint8 空间） | 模拟传感器噪声 |

## 3. 模型架构

### 3.1 第一阶段：隐式方案（无高度输入）

直接微调 openpilot 预训练模型，不修改架构。

```
输入：
  img_narrow: (B, 12, 128, 256) uint8  — 窄焦双帧 YUV420
  img_wide:   (B, 12, 128, 256) uint8  — 广角双帧 YUV420

PretrainedVisionModel（openpilot ONNX 提取，23M 参数）
  ├── Backbone（~22M 参数）
  │   ├── Stem + Stage 0-1（底层特征）
  │   ├── Stage 2-3（中高层特征）
  │   └── GAP + FC → (B, feature_dim)
  ├── Head Group 1（lane_lines, road_edges, lead, lead_prob, lane_lines_prob）
  └── Head Group 2（pose, road_transform, wide_from_device_euler）

输出：977 维扁平向量（与 openpilot 格式兼容）
  ├── pose:                   12 dims (6 mean + 6 log_sigma)
  ├── wide_from_device_euler:  6 dims (3 mean + 3 log_sigma)
  ├── road_transform:         12 dims (6 mean + 6 log_sigma)
  ├── lane_lines:            528 dims (4×33×4 MDN)
  ├── lane_lines_prob:         8 dims (4×2)
  ├── road_edges:            264 dims (2×33×4 MDN)
  ├── lead:                  144 dims (3×6×8 MDN)
  └── lead_prob:               3 dims
```

**batch>1 处理**：openpilot ONNX 固定 batch=1，onnx2torch 转换后的 PyTorch 模型需验证 batch>1 是否正常工作。若不支持，训练时通过循环逐样本推理后拼接。

### 3.2 第二阶段：显式方案（HeightConditionedHead）

在第一阶段微调后的模型基础上，添加高度条件化头部。

```
输入（新增）：
  camera_height: (B, 1) float32  — 相机安装高度（米）

HeightEmbedding（正弦位置编码，8 维）：
  将标量高度映射为连续嵌入向量，提供平滑插值能力

  freq = [1, 2, 4, 8]  # 4 个频率
  emb = concat([sin(freq * h), cos(freq * h)])  # → (B, 8)

HeightConditionedHead（~250K 参数）：
  输入：concat([backbone_feature(B, feature_dim), height_emb(B, 8)])
  → FC(feature_dim+8, 512) → ReLU → ResBlock(512) → ResBlock(512)
  → 各输出头 FC(512, out_dim)

完整流程：
  PretrainedVisionModel.backbone(img_narrow, img_wide)
    → feature: (B, feature_dim)
    → HeightConditionedHead(feature, camera_height)
    → 977 维输出
```

**HeightEmbedding 的归一化**：

```python
# 高度归一化到 [0, 1] 范围后再编码
h_norm = (camera_height - 1.0) / 2.0  # 1.0m→0, 3.0m→1
```

**第二阶段训练策略**：

1. 冻结第一阶段微调后的 backbone
2. 只训练 HeightConditionedHead（~250K 参数）
3. 若精度不足，全量端到端微调（lr=1e-5）

## 4. 训练方法

### 4.1 渐进式解冻策略

从输出层开始逐步解冻更深层，允许模型逐层适应新高度数据。

```
Phase 1（Epoch 1–10）：仅解冻输出头
  → 输出头快速适应多高度标签分布
  → Backbone 完全冻结，保留预训练特征

Phase 2（Epoch 11–20）：解冻 Stage 3 + FC 层
  → 高层特征开始适应多高度空间分布
  → 底层仍冻结，保护边缘/纹理检测能力

Phase 3（Epoch 21–40）：解冻 Stage 2
  → 中层空间几何特征适应不同高度的透视变化
  → Stage 0-1 + Stem 仍冻结

Phase 4（Epoch 41+，可选）：全量解冻
  → 极小 lr（5e-6），精细调整所有参数
  → 仅在 Phase 3 精度不足时启用
```

**Phase 切换条件**：除固定 epoch 边界外，要求验证集 loss 在当前 phase 内已收敛（连续 3 epoch 下降 < 1%）后才进入下一 phase。

### 4.2 分层学习率

```python
param_groups = [
    # Phase 1: 仅这组可训练
    {'params': output_heads.parameters(),        'lr': 1e-4,  'name': 'heads'},

    # Phase 2 起解冻
    {'params': backbone.fc.parameters(),         'lr': 5e-5,  'name': 'fc'},
    {'params': backbone.stage3.parameters(),     'lr': 3e-5,  'name': 'stage3'},

    # Phase 3 起解冻
    {'params': backbone.stage2.parameters(),     'lr': 1e-5,  'name': 'stage2'},

    # Phase 4 起解冻（可选）
    {'params': backbone.stage1.parameters(),     'lr': 5e-6,  'name': 'stage1'},
    {'params': backbone.stage0.parameters(),     'lr': 5e-6,  'name': 'stage0'},
    {'params': backbone.stem.parameters(),       'lr': 0,     'name': 'stem'},  # 始终冻结
]
```

**冻结实现**：未激活 phase 的参数组 `lr=0` 且 `requires_grad=False`。phase 切换时，修改 `requires_grad=True` 并设置目标 lr。

### 4.3 损失函数

#### 4.3.1 MDN 输出的 GaussianNLL 损失

对 `lane_lines`、`road_edges`、`lead`、`pose`、`road_transform`、`wide_from_device_euler` 等连续值输出，模型输出 `(mean, log_sigma)` 对，使用高斯负对数似然损失：

```
L_nll = 0.5 * [log_sigma + (target - mean)² / exp(2 * log_sigma)]
```

**log_sigma 截断**：`clamp(log_sigma, min=-3.0, max=3.0)`，防止 sigma 过小导致梯度爆炸（已知问题，见 MEMORY.md）。

#### 4.3.2 分类输出的 BCE 损失

对 `lane_lines_prob`、`lead_prob`：

```
L_bce = BCE_with_logits(predicted_logit, target_prob)
```

#### 4.3.3 总损失与各分量权重

```python
LOSS_WEIGHTS = {
    'lane_lines':             1.0,   # LDW 核心
    'lane_lines_prob':        1.0,   # LDW 核心
    'road_edges':             1.0,   # LDW 辅助
    'lead':                   0.5,   # FCW 核心（降权以缓解 MDN 不稳定）
    'lead_prob':              1.0,   # FCW 核心
    'pose':                   0.2,   # 辅助任务
    'road_transform':         0.2,   # 辅助任务（含高度估计）
    'wide_from_device_euler': 0.2,   # 辅助任务
}
```

**road_transform 权重说明**：虽然 `road_transform[2]` 包含高度估计（对 calibrationd 至关重要），但 road_transform 整体权重保持 0.2，避免高度回归任务主导训练过程。高度估计的准确性主要依赖 backbone 对透视关系的理解，而非损失权重的放大。

#### 4.3.4 MDN 格式说明

模型输出遵循 openpilot 非交错格式 `[all_means | all_log_sigma]`：

| 输出 | 总维度 | 均值维度 | log_sigma 维度 |
|------|--------|---------|---------------|
| lane_lines | 528 | 前 264 (4×33×2) | 后 264 |
| road_edges | 264 | 前 132 (2×33×2) | 后 132 |
| lead | 144 | 前 72 (3×6×4) | 后 72 |
| pose | 12 | 前 6 | 后 6 |
| road_transform | 12 | 前 6 | 后 6 |
| wide_from_device_euler | 6 | 前 3 | 后 3 |

### 4.4 优化器与调度器

```python
optimizer = AdamW(
    param_groups,       # 分层学习率（见 §4.2）
    weight_decay=1e-4,  # L2 正则化，约束权重偏离预训练
)

# Warmup + Cosine Annealing
scheduler = CosineAnnealingWarmRestarts(
    optimizer,
    T_0=10,            # 第一个周期 10 epochs
    T_mult=2,          # 周期倍增：10, 20, 40 epochs
    eta_min=1e-6,      # 最小学习率
)

# 前 5 epoch 线性 warmup（从 lr × 0.01 升至 lr）
warmup_scheduler = LinearLR(
    optimizer,
    start_factor=0.01,
    total_iters=5 * steps_per_epoch,
)

# 组合
scheduler = SequentialLR(
    optimizer,
    schedulers=[warmup_scheduler, scheduler],
    milestones=[5 * steps_per_epoch],
)
```

**梯度裁剪**：`torch.nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)`

### 4.5 灾难性遗忘防护

全量微调 23M 参数时必须防止标准高度（H1=1.22m）性能退化。

**防护措施矩阵**：

| 措施 | 实现方式 | 监控指标 |
|------|---------|---------|
| **H1 退化验证集** | §2.3 单独抽选的 H1 专用验证集，不参与训练 | val_loss_H1（每 epoch 计算） |
| **分层学习率** | 底层 lr ≤ 高层 lr 的 1/10 | 各层 lr 日志 |
| **L2 正则化** | weight_decay=1e-4 | 参数范数偏移 |
| **Early stopping（双指标）** | val_loss_total + val_loss_H1 | 若 H1 验证 loss 上升 > 5%，回滚 |
| **渐进式解冻** | Phase 1→4 逐步解冻 | 各 phase 的 H1 精度 |
| **权重偏移监控** | 每 epoch 计算 `‖θ - θ_pretrained‖₂` | 不超过预训练范数的 10% |

**Early stopping 双指标规则**：

```
条件1（总体）：val_loss_total 连续 patience 个 epoch 未下降 → 停止
条件2（锚定保护）：在 §2.3 的 H1 退化验证集上计算 val_loss_H1，
                  若相比 epoch 0（预训练权重基线）上升 > 5% → 停止并回滚

patience = 20 epochs
回滚目标：val_loss_H1 最佳时刻的 checkpoint
```

## 5. 评价方法

### 5.1 评价指标体系

评价指标分为三个层级：**模型输出级**、**功能级**、**系统级**。

```
Layer 1：模型输出级指标（逐输出头）
  └── 各输出分量的预测误差

Layer 2：功能级指标（LDW / FCW）
  └── 贴近实际使用场景的功能性评价

Layer 3：系统级指标（综合）
  └── 跨高度泛化、退化检测
```

### 5.2 分高度独立评价

**对每个高度档位 H_k (k=1..6) 独立计算以下指标**：

#### 5.2.1 车道线指标

| 指标 | 定义 | 计算方式 | 意义 |
|------|------|---------|------|
| **y_lat MAE (m)** | 车道线横向位置平均绝对误差 | `mean(\|y_pred - y_gt\|)` 对所有有效点 | LDW 核心精度 |
| **y_lat MAE @距离段** | 按前向距离分段的 MAE | 分段：[10,30m], [30,60m], [60,100m], [100,192m] | 近/中/远场精度分布 |
| **z_height MAE (m)** | 车道线高度分量 MAE | `mean(\|z_pred - z_gt\|)` | 高度估计精度 |
| **lane_prob AUC** | 车道线存在概率 ROC-AUC | 以 GT prob > 0.5 为正样本 | 检测可靠性 |
| **lane_prob F1** | 车道线检测 F1 score | 阈值 0.5 | 检测精度/召回平衡 |

#### 5.2.2 路沿指标

| 指标 | 定义 |
|------|------|
| **road_edge y_lat MAE (m)** | 路沿横向位置误差 |
| **road_edge z_height MAE (m)** | 路沿高度误差 |

#### 5.2.3 前车指标

| 指标 | 定义 | 计算方式 |
|------|------|---------|
| **lead x_fwd MAE (m)** | 前车纵向距离误差 | 仅对 GT lead_prob > 0.3 的帧 |
| **lead y_lat MAE (m)** | 前车横向位置误差 | 同上 |
| **lead_prob AUC** | 前车存在检测 ROC-AUC | 以 GT lead_prob > 0.3 为正样本 |
| **lead detection rate** | 前车检测率 | 预测 prob > 0.3 且 GT prob > 0.3 的帧占比 |

#### 5.2.4 运动估计指标

| 指标 | 定义 |
|------|------|
| **pose trans MAE (m/s)** | 平移速度误差 |
| **pose rot MAE (rad/s)** | 旋转角速度误差 |
| **road_transform[2] MAE (m)** | 高度估计误差（calibrationd 输入） |

### 5.3 跨高度泛化测试

验证模型在**未见高度**上的泛化能力，特别是训练档位之间的插值性能。

#### 5.3.1 插值测试

从测试集中选取部分 session，在 Carla 中增采 **中间高度** 数据用于纯评价（不参与训练）：

| 测试高度 | 相邻训练高度 | 预期行为 |
|---------|------------|---------|
| 1.10m | H1(1.22)–下界 | 外推（低于最低训练高度） |
| 1.40m | H2(1.3)–H3(1.5) | 插值 |
| 1.75m | H3(1.5)–H4(2.0) | 插值 |
| 2.25m | H4(2.0)–H5(2.5) | 插值 |
| 2.75m | H5(2.5)–H6(3.0) | 插值 |

**判定标准**：插值高度的 y_lat MAE 应不超过其相邻两个训练高度 MAE 的线性插值值的 1.5 倍。

```
MAE(H_interp) ≤ 1.5 × lerp(MAE(H_low), MAE(H_high), t)
其中 t = (H_interp - H_low) / (H_high - H_low)
```

#### 5.3.2 高度敏感性曲线

绘制 **y_lat MAE vs camera_height** 曲线（含训练高度和插值高度），检查：

1. 曲线单调递增（偏离 H1 越远误差越大，预期行为）
2. 无突变或震荡（模型行为平滑）
3. 插值点落在训练点之间（无过拟合导致的插值凹陷）

### 5.4 功能级评价：LDW

LDW（车道偏离预警）的核心在于**横向位置精度**。

#### 5.4.1 横向偏移检测精度

```
对每帧计算：
  自车横向偏移 = (left_lane_y + right_lane_y) / 2
  偏移检测误差 = |offset_pred - offset_gt|

评价方式：
  1. 偏移检测误差的中位数（各高度独立）
  2. 偏移检测误差 < 0.1m 的帧占比（准确率）
  3. 偏移检测误差 < 0.2m 的帧占比（宽容率）
```

#### 5.4.2 LDW 触发一致性

```
定义 LDW 触发条件：
  |offset| > lane_width/2 - vehicle_width/2 - margin
  其中 margin = 0.3m（预警提前量）

计算指标：
  true_positive:   GT 触发且模型触发
  false_positive:  GT 未触发但模型触发
  false_negative:  GT 触发但模型未触发

报告：precision, recall, F1
```

#### 5.4.3 LDW 距离分段评价

| 距离段 | 覆盖范围 | LDW 功能意义 |
|--------|---------|-------------|
| **近场** | 10–30m | 即时预警区域 |
| **中场** | 30–60m | 主要工作区域 |
| **远场** | 60–100m | 前瞻预警 |
| **超远场** | 100–192m | 路径规划参考 |

每个距离段独立报告 y_lat MAE。

### 5.5 功能级评价：FCW

FCW（前车碰撞预警）的核心在于**前车纵向距离精度**和**检测可靠性**。

#### 5.5.1 前车检测评价

```
对存在前车的帧（GT lead_prob[0] > 0.3）：
  1. 纵向距离误差：|x_pred - x_gt| (m)
  2. 横向位置误差：|y_pred - y_gt| (m)
  3. TTC（碰撞时间）误差：|TTC_pred - TTC_gt| (s)
     TTC = x_fwd / max(v_ego - v_lead, 0.1)

检测级指标：
  4. 检测率（recall）：正确检测到前车的帧占比
  5. 误报率（false positive rate）：无前车时错误检出的帧占比
```

#### 5.5.2 FCW 距离分段评价

| 距离段 | 覆盖范围 | FCW 功能意义 |
|--------|---------|-------------|
| **紧急区** | 5–15m | 紧急制动预警（乘用车）/无效区（卡车 H=3m, X_min=9.3m） |
| **预警区** | 15–30m | 正常预警区域 |
| **前瞻区** | 30–100m | 前瞻减速提示 |

**高度相关说明**：H6 (3.0m) 的近场盲区为 9.3m，因此 H6 在 [5, 9.3m] 距离段无法评价，在 [9.3, 15m] 段可能精度下降，这是物理限制而非模型缺陷。评价报告中应标注各高度的有效评价距离下限。

### 5.6 退化检测：锚定高度保护

**目的**：确保微调后模型在标准高度（H1=1.22m）上不退化。

**基线建立**：微调前，用预训练模型在测试集 H1 数据上计算所有指标，作为退化检测基线。

**退化判定**：

```
对每个指标 M ∈ {y_lat MAE, lead x MAE, lane_prob AUC, ...}：
  退化率 = (M_finetuned - M_pretrained) / M_pretrained × 100%

红线规则：
  - y_lat MAE 退化 > 10%  → ❌ 不可接受
  - lead x MAE 退化 > 15% → ❌ 不可接受
  - lane_prob AUC 退化 > 3% → ❌ 不可接受
  - road_transform[2] MAE 退化 > 20% → ⚠️ 警告

任一红线触发 → 回滚到上一个满足条件的 checkpoint，调整训练策略
```

### 5.7 阶段判定标准

#### 5.7.1 第一阶段（隐式方案）达标标准

| 高度 | y_lat MAE 近场 [10,30m] | y_lat MAE 中场 [30,60m] | lead x MAE [15,100m] | lane_prob AUC | 达标等级 |
|------|------------------------|------------------------|---------------------|---------------|---------|
| H1 (1.22m) | < 0.10m | < 0.06m | < 2.0m | > 0.95 | **基线** |
| H2 (1.30m) | < 0.10m | < 0.06m | < 2.0m | > 0.95 | **必须达标** |
| H3 (1.50m) | < 0.12m | < 0.08m | < 2.5m | > 0.93 | **必须达标** |
| H4 (2.00m) | < 0.20m | < 0.12m | < 3.0m | > 0.90 | **目标达标** |
| H5 (2.50m) | < 0.25m | < 0.15m | < 3.5m | > 0.88 | **目标达标** |
| H6 (3.00m) | < 0.30m | < 0.18m | < 4.0m | > 0.85 | **最低要求** |

**判定逻辑**：

```
若所有高度达到"目标达标"水平：
  → 第一阶段成功，直接部署隐式模型

若 H1–H3 达标但 H4–H6 不足：
  → 进入第二阶段（显式方案）

若 H1–H2 退化：
  → 训练策略有问题，回滚并调整
```

#### 5.7.2 第二阶段（显式方案）达标标准

在第一阶段基础上，额外要求：

1. **中间高度插值**：所有 5 个插值高度（§5.3.1）满足 1.5× 线性插值约束
2. **H5/H6 精度提升**：相比第一阶段，y_lat MAE 降低 ≥ 15%
3. **H1 无退化**：所有指标退化 < 5%
