# 坡道场景 2D 投影异常分析

## 背景

使用 `inspect_clean_log.py` / `inspect_annotated.py` 可视化工具检查坡道场景数据时，
发现两类投影异常：

1. **Lead（前车）标注投影到半空中** — 在接近坡道顶部时尤为明显
2. **Lane line / Road edge 远端飘入天空** — 车道线和路沿多边形的远端脱离路面

两者的根因不同，下面分别分析。

---

## 问题一：Lead 投影偏高（已修复）

### 数据语义

modeld 的 lead 输出格式为 `[3, 6, 4]`（3 个候选 × 6 个时间步 × 4 维），
4 维含义为 `[x, y, v, a]`：

| 维度 | 含义 | 单位 |
|------|------|------|
| x | 前向水平距离 | m |
| y | 横向偏移（右为正）| m |
| v | 前车绝对速度 | m/s |
| a | 前车加速度 | m/s² |

**不包含 z（垂直高度）坐标。** 这是 openpilot LeadDataV3 格式的设计限制。

### 投影方法

可视化代码 `draw_leads()` 将 lead 投影到 2D 图像时需要 z 坐标。
由于数据中没有 z，原实现使用**静态 camera_height**（相机安装高度）作为常数：

```python
uv = project_pts([x_dist], [y_off], [camera_height], T_disp)
```

### 坡道上的失效机制

投影公式（简化，rpyCalib ≈ 0 时）：

```
pixel_v = f × z / x + cy
```

| 场景 | 实际 z | 使用的 z | pixel_v 偏差 | 视觉效果 |
|------|--------|---------|-------------|---------|
| 平路 | ≈ camera_height | camera_height | 无 | 正确 |
| 坡顶后下坡的前车 | >> camera_height | camera_height | pixel_v 偏小 | **前车浮在空中** |
| 上坡中的前车 | < camera_height | camera_height | pixel_v 偏大 | 前车偏低 |

```
                    camera_height (恒定)
    ego车 ——————|——————
          ↗ 上坡    ↘ 下坡
                        ·  ← 实际前车位置 (z_real >> camera_height)
                     ·     ← 错误投影位置 (z = camera_height)
```

### 根因

**投影方法问题**：用静态 camera_height 代替真实 z，等于假设平路。
3D 标注数据本身没有质量问题（采集时计算了正确的 3D 位置，但 z 未保留在 lead 格式中）。

### 修复方案（已实施）

从 lane line 的 z 坐标插值估算 lead 所在位置的路面高度。

算法：`_estimate_lead_z(x_lead, y_lead, lane_lines, lane_probs, camera_height)`

1. **沿纵向插值**：对每条车道线 i，在 x_lead 处 `np.interp` 得到 `(y_i, z_i)`
2. **加权组合**：`w_i = prob_i × exp(-d_lat² / 2σ²)`，其中 `d_lat = |y_i - y_lead|`，`σ = 2.0m`
3. **加权平均**：`z_est = Σ(w_i × z_i) / Σ(w_i)`
4. **回退**：无有效车道线时回退到 camera_height

修改位于 `tools/dashcam/viz/inspect_annotated.py`。可通过 `--no-lead-z` 参数禁用插值、
回退到原始的 camera_height 投影，便于对比。

## 问题二：Lane line / Road edge 远端飘入天空

### 数据语义

与 lead 不同，车道线和路沿的数据**包含 z 坐标**：

- lane_lines: `(4, 33, 3)` — 4 条线 × 33 个采样点 × `[x, y, z]`
- road_edges: `(2, 33, 3)` — 2 条线 × 33 个采样点 × `[x, y, z]`

x 取自 X_IDXS（33 个固定前向距离），范围 0 ~ 192m（二次采样，近密远疏）。

所以这不是缺少 z 的问题，根因在别处。

### 根因一：3D→2D 透视投影不处理遮挡

这是**几何层面**的根本原因。

在坡道顶部，坡顶后方的路面被坡面遮挡，相机无法看到。但 3D→2D 透视投影是纯数学映射，
不考虑可见性——它会将**所有** 3D 点投影到图像平面，包括被遮挡的点。

```
投影到图像中的位置：

    ───────────── 天空 ─────────────
         ×  ← X_IDXS[23]=99m 的投影（天空区域）
       ×     ← X_IDXS[20]=75m 的投影
    ------坡顶线------- ← 可见路面终点（例如 50m）
    //// 可见路面 ////
    /////////////////
```

坡顶后路面点的投影坐标 `v = f × z / x + cy` 落在坡顶线之上的天空区域。
视觉上车道线多边形从路面延伸到了天空中。

**即使模型的 z 预测完全正确，这个问题仍然存在**——这是透视投影的固有限制。

### 根因二：modeld 对不可见路面的 z 外推不准

在根因一之上，模型的 z 预测质量使问题**加剧**。

modeld 对全部 33 个 X_IDXS 采样点输出 `(y, z)` 预测，包括超出可见范围的远处点。
在坡道顶部：

- **可见区间**（0 ~ 坡顶距离）：模型有视觉证据，z 预测准确
- **遮挡区间**（坡顶距离 ~ 192m）：模型无视觉证据，倾向于沿可见趋势**线性外推**

上坡时 z 随距离递减（路面升高接近相机水平面）。模型将此趋势延续到坡顶后，
预测出过小的 z 值（甚至负值，意味着路面高于相机）。这使得投影点进一步偏离，
深入天空区域，比正确 z 值的情况更加严重。

| 数据来源 | z 趋势（坡顶后） | 投影偏离程度 |
|---------|-----------------|-------------|
| 正确的路面 z | z 递增（路面下降） | 略高于坡顶线 |
| modeld 外推 z | z 继续递减（错误） | 远高于坡顶线，深入天空 |

### 根因三：可视化未裁剪到可见地平线

当前裁剪机制：

```python
MAX_DRAW_DISTANCE = 100.0  # 固定值，不感知坡道
max_idx = _get_path_length_idx(path_xs, max_dist)
```

`MAX_DRAW_DISTANCE = 100m` 是固定阈值，不随坡道几何变化。
在坡顶距离为 30~50m 的场景中，50~100m 范围内的点全部位于遮挡区，
仍被绘制出来。

### 三者叠加效应

```
根因一（几何遮挡）  ──→  远端点投影到天空区域
        +
根因二（z 外推错误）──→  投影偏离进一步加剧
        +
根因三（无动态裁剪）──→  不应绘制的点仍被绘制
        ↓
    视觉效果：车道线/路沿远端飘入天空
```

---

## 与 openpilot 原生 UI 的对比

openpilot 原生 UI 中同样存在此几何限制，但通过以下方式缓解：

- **MAX_DRAW_DISTANCE 裁剪**：限制绘制范围
- **车道线极窄**：多边形宽度 = `prob × 0.025m`，远处即便错位也不醒目
- **实时 rpyCalib**：包含动态 pitch，warp 矩阵更准确地校正坡道倾斜
- **置信度衰减**：远处预测置信度自然下降，渲染透明度降低

---

## 可能的改进方向

### 方向一：动态可见地平线裁剪

检测投影后的 v 坐标反转点（车道线从"向远处收敛"变为"向上发散"），
将其作为可见地平线，裁剪之后的点不绘制。

### 方向二：基于 z 梯度的异常检测

监测相邻采样点的 z 变化率。当 z 梯度突变（从递减突变为继续递减但斜率异常）
时，认为已超出可见范围，截断绘制。

### 方向三：降低远端渲染权重

对远距离点的多边形透明度按距离衰减，使错位区域自然淡出，不影响近端准确区域的可视化。
